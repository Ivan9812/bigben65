# BIG BEN — сайт по дизайн-макетам

React 19 + Vite, анимации Motion, Node.js / Express и PostgreSQL 17. Исходный просмотрщик и все макеты в корне репозитория сохранены.

## Посмотреть без установки

Готовая версия уже включена в репозиторий: [preview/index.html](preview/index.html). В GitHub нажмите **Download raw file**, сохраните файл и откройте его в браузере. [Компьютер](preview/home-desktop.png) · [Телефон](preview/home-mobile.png) · [Архив исходников](preview/bigben-site-source.zip).

После сборки откройте `dist/bigben-preview.html` в браузере двойным щелчком. Это самостоятельный файл: весь JavaScript, CSS, изображения и иллюстрации встроены. Интернет и сервер не нужны. Маршруты используют `#`, поэтому страницы работают и при открытии файла. Этот файл всегда использует локальный деморежим, даже если его разместить на обычном статическом хостинге.

В этом режиме корзина, избранное, профиль, обращения и демозаказы сохраняются в браузере. Если браузер запрещает хранилище для локальных файлов, просмотр каталога доступен, но сохранение может быть ограничено.

## Запуск с PostgreSQL

Нужны Node.js 22.12+ (или 20.19+) и Docker с Compose. Команды выполняются из `website/`:

```bash
npm ci --cache /tmp/bigben-npm-cache
npm run db:up
npm run build
npm start
```

Сайт обслуживается на порту 3000. `db:up` создаёт локальный случайный пароль в игнорируемом `.env` и запускает PostgreSQL на локальном порту 5433. Заказы и обращения сохраняются в PostgreSQL; том Docker остаётся после остановки контейнера. Для существующей БД укажите `DATABASE_URL` в своём `.env`. Не добавляйте этот файл в Git.

Для разработки с обновлением страницы:

```bash
npm run db:up
npm run dev
```

Vite использует порт 5173 и перенаправляет `/api` в Node.js на порт 3000. Остановка БД без удаления данных: `npm run db:down`. Удаление тома не входит в настройку.

## Что работает

- Адаптивные страницы из карты макетов: главная, каталог и категории, бренды, товары, поиск, избранное, сравнение, корзина и оформление; демокабинет, магазины, сервис, журнал, справочные и правовые страницы, FAQ и 404.
- Фильтры по бренду, механизму и цене; сортировка; увеличение изображения товара.
- Избранное, сравнение до четырёх моделей, количество и сумма корзины, удаление с отменой; состояние сохраняется при перезагрузке.
- Сервер проверяет состав заказа и контакты, рассчитывает цену по каталогу и предотвращает дубли при повторной отправке одного запроса.
- Формы обращения, сервисной заявки и записи на примерку сохраняют учебные обращения.
- Появление секций, переходы страниц, реакции карточек и уведомления. Настройка `prefers-reduced-motion` учитывается.
- Диалоги используют нативный `<dialog>`: Escape, возврат фокуса и недоступный фон.

## Границы демоверсии

Это работающая демонстрация, а не запущенный магазин. Цены и иллюстрации демонстрационные. Заказы не резервируют товары, не отправляются магазину и не запускают доставку; платёжные списания отсутствуют. Реальная авторизация, программа лояльности, email/SMS, склад и платежи не подключены. Демопрофиль не имеет пароля и не служит защищённым аккаунтом. Адреса, контакты и правовые тексты необходимо подтвердить перед коммерческим запуском.

## Проверки

```bash
npm test
# При работающих сервере и PostgreSQL:
node scripts/check-api.mjs
# При установленном Python Playwright и /usr/bin/chromium:
python3 scripts/check-browser.py
```

API-проверка использует только локальный сервер и удаляет созданную ею тестовую запись. Браузерная проверка создаёт синтетические демозаказ и обращение, проверяет маршруты на ширинах 1440 и 390 px, функции покупки и самостоятельный HTML без обращений к API. Для неё нужны `python3 -m pip install playwright` и Chromium; в подготовленной облачной среде они уже есть. Облачные скриншоты сохраняются вне репозитория в `/workspace/artifacts`; путь можно изменить переменной `BIGBEN_ARTIFACTS`.

В облачном Chromium политика администратора запрещает `file://`. Поэтому автономный файл проверяется через HTTP в том же локальном режиме; открытие двойным щелчком на пользовательском компьютере отдельно не проверено.
